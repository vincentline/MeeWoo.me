## 一、背景与目标

### 现状问题

当前 `src/gadgets/png_compression.html` 是一个纯浏览器端 PNG 批量压缩工具，使用 TinyPNG WASM 内核。交互存在以下问题：

| 问题 | 严重度 |
|:---|:---|
| 只能拖拽添加文件，无「点击选择文件」按钮 | 高 |
| 图片列表缺少尺寸信息（宽×高），无删除单张能力 | 高 |
| 无压缩前后画质对比预览 | 高 |
| 调整压缩级别后看不到效果，只能盲调 | 高 |
| 压缩过程进度不可见，无可取消机制 | 中 |
| 多次调参数重复压缩导致下载重复 | Bug |
| 压缩级别是裸数值滑块（10-100），无语义说明 | 中 |
| 下载不能勾选，只能全量打包或逐张下 | 中 |

### 优化目标

全面重构交互，打造一个"好用"的 PNG 压缩工具：所见即所得、每一步有反馈、操作可撤销。

### 已钉死的需求

| 维度 | 决策 |
|:---|:---|
| 文件输入 | 拖拽 **+** 点击选择文件 |
| 列表管理 | 展示宽×高尺寸 + 文件大小；可删除单张；可追加新图 |
| 对比预览 | 点击缩略图弹出大图弹窗，左右原图/压缩后对比，中间可拖拽分割线 |
| 对比压缩 | 弹窗右侧可选多种压缩率试压，底部 tab 切换不同压缩率效果，选定一版为「确认版本」 |
| 压缩流程 | 列表每张图有实时进度条 + 可取消按钮；重新压缩替换旧结果 |
| 压缩级别 | 预设档位（极致压缩 / 推荐 / 高质量）+ 可展开的自定义滑块 |
| 下载 | 列表多选勾选 + 打包下载；只下载确认版本 |
| 约束 | 纯浏览器端（不上传服务器）、保留暗黑模式 |
| 技术栈 | 保持纯 HTML/CSS/JS，不引入 Vue/React |

## 二、实现思路

### 总体架构

不改变文件组织方式（仍为 `png_compression.html` + `.css` + `.js` 三文件），在现有基础上做以下改造：

```
src/gadgets/
  png_compression.html   ← DOM 结构重写
  png_compression.css    ← 样式重写（保留设计系统令牌）
  png_compression.js     ← 逻辑重写（保留压缩服务调用）
```

依赖关系不变：
- 全局样式：`src/assets/css/styles.css`（重置与基础布局）
- 设计令牌：本地定义于 `png_compression.css`（CSS 变量如 `--primary-blue`、`--radius-md` 等）
- 压缩服务：`src/assets/js/service/image-compression-service.js`（封装 TinyPNG）
- JSZip：`src/assets/js/lib/jszip.min.js`

### 关键组件设计

#### 1. 文件输入区（复用 + 新增）

保留现有拖拽区，新增「选择文件」按钮和隐藏 `<input type="file">`：

```html
<section class="drag-area">
  <div class="drag-area-content">
    <svg class="drag-icon">...</svg>
    <h2>拖入 PNG 图片进行压缩</h2>
    <p>或</p>
    <button class="btn-select-files">选择文件</button>
  </div>
</section>
```

列表出现后，拖拽区缩小为紧凑的「添加更多」条，始终可见。

#### 2. 图片卡片（重写）

每张图片一个卡片，包含：

```
┌──────────────────────────────┐
│ ☐  [缩略图]          [×删除] │
│    文件名.png                │
│    1920 × 1080 · 2.4 MB     │
│    压缩后: 320 KB (-87%)    │  ← 压缩完成后显示
│    状态: ✓ 已完成            │
│    ████████████░░ 进度条     │  ← 压缩中显示
│                              │
│    [确认版本: 推荐 120KB]    │  ← 对比压缩确认后
└──────────────────────────────┘
```

#### 3. 压缩级别选择器（重写）

预设档位用按钮组 + 可展开的自定义滑块：

```html
<div class="quality-presets">
  <button class="preset-btn active" data-quality="40">极致压缩</button>
  <button class="preset-btn" data-quality="70">推荐</button>
  <button class="preset-btn" data-quality="90">高质量</button>
  <button class="preset-btn preset-custom">自定义 ▾</button>
</div>
<div class="quality-custom" style="display:none">
  <input type="range" min="10" max="100" value="70">
  <span class="quality-value">70</span>
</div>
```

> **参数映射说明**：TinyPNG 使用 `set_quality(minimumQuality, quality)` 双参数模型，`minimumQuality` 由压缩服务固定为 30。预设档位的 `data-quality` 仅控制 `quality` 上限。例如「极致压缩」实际等效于 `set_quality(30, 40)`——允许质量在 30-40 间波动。

#### 4. 对比预览弹窗（全新）

全屏居中模态弹窗，包含：
- **左侧**：原图（`<img>` 显示）
- **右侧**：压缩后图片（`<canvas>` 渲染，支持多压缩率切换）
- **分割线**：可拖拽的竖线，左右移动改变两侧可见区域（CSS clip-path 实现）
- **对比压缩按钮**：点击弹出压缩率选择面板（预设 + 自定义输入）
- **压缩率 Tab**：底部横向排列，每试压一个压缩率就新增一个 tab
- **确认按钮**：点击后将当前选中的压缩率设为该图的「确认版本」

技术实现：
- 分割线对比：两图统一缩放到弹窗可视区域内的同一尺寸，使用绝对定位叠加（`position: absolute; top: 0; left: 0`）保证像素级对齐。上层图用 `clip-path: inset(0 0 0 Npx)` 控制可见宽度，`mousedown/mousemove/mouseup` 拖拽分割线改变 N 值
- 尺寸假设：TinyPNG 保持原图尺寸不变（当前 tinypng-lib 实测确实不变），若未来版本改变，两图缩放策略确保对齐
- 多压缩率结果缓存在内存中（`Map<quality, Uint8Array>`，单图试压总缓存上限 100MB）

#### 5. 双路径压缩决策表（批量 vs 对比弹窗）

主列表「开始压缩」和对比弹窗「对比压缩」是两条独立的压缩路径，数据覆盖规则如下：

| 场景 | 触发方式 | 压缩范围 | 结果用途 | 覆盖规则 |
|:---|:---|:---|:---|:---|
| 批量压缩 | 主列表点击「开始压缩」 | 所有图片，使用当前选中的预设档位/自定义值 | 为每张图产出一版默认结果 | 覆盖该图旧 `compressedData`，重置 `confirmedQuality` |
| 对比试压 | 弹窗内点击「对比压缩」→ 选压缩率 → 试压 | 仅当前图片，使用指定的单个压缩率 | 缓存到 `trialResults` Map，不改变主列表数据 | 不覆盖批量压缩结果，仅追加到试压缓存 |
| 确认版本 | 弹窗内点击「确认此版本」 | 当前图片 | 将指定压缩率的试压结果写入该图的 `compressedData`，设置 `confirmedQuality` | **覆盖**批量压缩结果，成为最终下载版本 |
| 跳过批量 | 不点「开始压缩」，直接点缩略图进弹窗试压后确认 | 仅当前图片 | 该图以确认版本为准，其余图无压缩结果 | 未确认的图下载时被跳过 |
| 批量后微调 | 先批量压缩 → 点缩略图进弹窗 → 试压不同质量 → 确认 | 当前图片 | 以确认版本覆盖批量结果 | 确认版本**覆盖**批量结果 |

**下载优先级**：每张图取 `confirmedQuality` 对应的 `compressedData` > 批量压缩的 `compressedData` > 跳过（未压缩）。

#### 6. 取消机制（新增）

使用 `AbortController` 模式（TinyPNG WASM 是同步阻塞的，实际不可中断），改为：
- 在每张图压缩前检查取消标记
- 点击取消后，当前图压缩完即停止，后续图不再压缩
- 已压缩的图保留结果

#### 6. 修复重复下载 Bug

根因：`downloadAll()` 遍历 `app.images` 中所有 `status === 'completed'` 的图，重新压缩时旧结果未清除。

修复：重新压缩前清空 `image.compressedData = null`，下载时检查是否有确认版本。

## 四、风险与边界

| 风险 | 缓解措施 |
|:---|:---|
| TinyPNG WASM 压缩是同步阻塞的，单图压缩期间 JS 定时器/rAF 均不触发，单图内进度必然从 0% 跳到 100% | ① 承认单图压缩期间 UI 必然冻结，使用 CSS `animation` 脉冲动画（非 JS 定时器）做不确定进度指示；② 利用 `for` 循环中 `await` 间隙做图间进度更新；③ 取消机制的真正价值在「图间跳过」，非「图内中断」 |
| 对比预览弹窗可能在大图时内存占用高 | 对预览图做 `canvas` 等比缩放显示，不直接加载原图到 `<img>` |
| 多压缩率缓存占用内存 | 限制最多 4 个压缩率 tab；切换图片时释放旧缓存 |
| 暗黑模式下弹窗样式需逐项适配 | CSS 中使用 `body.dark-mode` 选择器统一切换，参考现有 panel.css 实践 |
| 大分辨率图片（如 4000×3000）TinyPNG 压缩可能耗时 10 秒以上 | 在 Step 4 边界处理中增加分辨率阈值提示（如超过 3000px 任一边时 toast 提示"图片较大，压缩可能较慢"） |

**本轮不做**：
- 不改变 TinyPNG 压缩内核
- 不支持 PNG 以外的格式
- 不做历史记录持久化
- 不做图片尺寸调整（resize）功能

## 五、执行步骤

### Step 1：HTML 结构重写
- 新增「选择文件」按钮 + 隐藏 `<input type="file" multiple accept="image/png">`
- 拖拽区改为始终可见（列表出现后缩小为紧凑条）
- 图片列表改用卡片式布局，每张卡片含：勾选框、缩略图、文件名、尺寸、大小、删除按钮、状态/进度条
- 压缩级别改为预设按钮组 + 可展开自定义滑块
- 新增「取消压缩」按钮（初始隐藏）
- 压缩结果区改为「打包下载选中」按钮
- 新增对比预览弹窗 DOM（初始隐藏）：左右图区、分割线、压缩率 tab 栏、确认按钮

### Step 2：CSS 样式重写
- 基于设计系统令牌（CSS 变量）重写全部样式
- 文件输入区：紧凑模式样式
- 图片卡片：网格布局、hover 效果、暗黑模式
- 预设按钮组：选中态高亮
- 对比弹窗：全屏遮罩、左右分栏、分割线拖拽手柄、tab 样式
- 复刻现有暗黑模式适配模式（`body.dark-mode` 选择器）
- **WASM 冻结期反馈**：压缩中卡片显示 CSS `@keyframes` 脉冲动画（`opacity` 呼吸/`background` 流光），不依赖 JS 定时器——WASM 同步阻塞期间 JS 定时器不触发，但 CSS `animation` 仍能运行

### Step 3：JS 逻辑重写
- 重写 `app` 状态管理：新增 `confirmedQuality`、`trialResults`（Map）、`cancelled` 标记
- 文件处理：`processFiles()` 支持 input[file] + drop 两种来源；读取图片尺寸
- 图片卡片渲染：`renderImageCard()` 创建完整 DOM
- 删除单张：`removeImage(id)` 清理 DOM 和数据
- 压缩流程：`startCompression()` → 逐张压缩，每张前检查取消标记 → 更新进度
- 取消机制：设置 `app.cancelled = true`，`compressNext()` 检测到即停止
- 预设档位：`setQualityPreset(value)` 联动滑块
- 对比弹窗：`openCompareModal(image)` 加载原图 → `runTrialCompress(quality)` 试压 → `confirmVersion(quality)` 确认
- 分割线拖拽：`mousedown/mousemove/mouseup` 控制 `clip-path`
- 下载：`downloadSelected()` 只下载勾选 + 已确认版本的图
- 修复重复下载 bug：重新压缩前清空旧 `compressedData` 和 `confirmedQuality`

### Step 4：边界处理
- 无图片时压缩按钮禁用
- 压缩中禁止删除、禁止重复点击压缩
- 弹窗打开时禁止背景滚动
- 单个文件超过 50MB 时提示
- 图片分辨率任一边超过 3000px 时 toast 提示"图片较大，压缩可能较慢"
- 非 PNG 文件拖入时静默忽略 + toast 提示
- 压缩失败的单张标记为失败，不影响其他图片
- toast 样式从内联改为 CSS 类名，支持暗黑模式（`body.dark-mode` 下 toast 背景切换为 `rgba(255,255,255,0.9)` + 深色文字）
